# Развёртывание и проверка на своём сервере

Пошаговый сценарий: поднять систему, зарегистрироваться под разными
ролями, посмотреть, как всё работает, и убрать за собой.

Домен и учётная запись у почтового провайдера **не нужны**. Письма будут
печататься в журнал воркера — оттуда вы и возьмёте ссылку подтверждения.

---

## 1. Подготовка сервера

Проверьте, что на сервере есть Docker с плагином Compose, Python 3.11+
и `make`.

Отдельно — **файл подкачки**. На 1 ГБ оперативной памяти это разница
между «медленно» и «сервер умер»:

```
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

Файрвол: открыть только 22, 80 и 443. Учтите, что Docker вносит правила
в `iptables` в обход `ufw` — проверяйте через `iptables -L -n`, а не
через `ufw status`.

---

## 2. Первый запуск

```
git clone <репозиторий> selectashop
cd selectashop

make init-config
```

Команда создаст `config/selectashop.toml` и сгенерирует секреты: ключ
подписи, пароли четырёх ролей БД, три криптографических ключа, неугадываемый
путь админки.

Дальше откройте файл и впишите **одно** значение:

```toml
[network]
server_ip = "ВАШ_IP"
```

Затем:

```
make tls-selfsigned     # сертификат сайта на IP-адрес
make db-cert            # сертификат для канала приложение <-> БД
make config             # сгенерировать конфиги из единого файла
make build
make up
```

`make config` откажется работать, если TLS выключен при настроенной базе
данных: на сайте есть форма входа, и пароль по незашифрованному каналу
недопустим.

Проверка, что всё поднялось:

```
make ps
curl -k https://ВАШ_IP/healthz     # должно вернуть ok
```

---

## 3. Создание владельца магазина

Владелец создаётся **только из терминала**. Веб-страницы «создать первого
администратора» не существует намеренно: у такой операции не должно быть
сетевой поверхности вообще.

```
make create-owner ARGS="--username ВАШ_ЛОГИН --email ВАША_ПОЧТА"
```

Пароль будет запрошен интерактивно. Адрес сразу помечается подтверждённым,
учётная запись активна.

---

## 4. Проверка регистрации покупателя

Откройте в браузере `https://ВАШ_IP/accounts/register/`.

Браузер покажет предупреждение о сертификате — это ожидаемо. Сертификат
самоподписанный, доверенного центра за ним нет. Нажмите «Дополнительно» и
«Перейти». Трафик при этом шифруется; предупреждение исчезнет, когда
появится домен и Let's Encrypt.

Заполните форму. После отправки вы увидите страницу «Проверьте почту».

Теперь возьмите ссылку из письма:

```
make mail
```

В журнале воркера будет письмо целиком:

```
======================= ПИСЬМО (режим console) =======================
Кому:  buyer@example.com
Тема:  SelectaShop: подтвердите адрес почты
----------------------------------------------------------------------
...
https://ВАШ_IP/accounts/verify/xxxxxxxxxxxx/
```

Откройте эту ссылку и нажмите «Подтвердить».

> Кнопка нужна не для красоты. Корпоративные почтовые антивирусы сами
> открывают ссылки из писем, проверяя их. Если бы ссылка срабатывала при
> открытии, часть пользователей получала бы «ссылка устарела» ещё до того,
> как прочитала письмо.

Учётная запись активна. Войдите на `https://ВАШ_IP/accounts/login/` —
работает и логин, и адрес почты.

---

## 5. Проверка роли администратора

Зарегистрируйте вторую учётную запись тем же способом, затем повысьте её:

```
make grant-role ARGS="ЛОГИН admin"
```

Роль меняется только так. Ни одна форма на сайте не принимает поле роли,
и администратор не может назначать администраторов — это может только
владелец из терминала.

Чтобы увидеть разницу в правах, включите админку Django:

```toml
[django]
admin_enabled = true
```

```
make config && make restart
```

Адрес админки лежит в том же файле, в `[django].admin_url` — он
сгенерирован неугадываемым, чтобы боты не перебирали `/admin/`.

---

## 6. Проверка восстановления пароля

`https://ВАШ_IP/accounts/password-reset/` → указать адрес → `make mail` →
перейти по ссылке → задать новый пароль.

Обратите внимание: ответ одинаков для существующего и несуществующего
адреса. Иначе форма восстановления позволяла бы перебором выяснить, кто
зарегистрирован в магазине.

---

## 7. Уборка после проверки

```
# обезличивание: строка остаётся, данные человека удаляются
make delete-account ARGS="ЛОГИН --yes"

# полное удаление: строки не остаётся вовсе
make delete-account ARGS="ЛОГИН --hard --yes"
```

Без `--yes` команда попросит подтвердить, введя логин целиком.

Разница существенна. **Обезличивание** — боевой режим: строка пользователя
нужна, чтобы на неё ссылались будущие заказы, которые придётся хранить для
бухгалтерии. Адрес и логин при этом удаляются физически и освобождаются.
**Полное удаление** возвращает базу в исходное состояние и годится только
для тестовых записей — вместе с пользователем исчезнет история его заказов.

Единственного владельца магазина удалить нельзя: команда откажет, чтобы
проект не остался без административного доступа.

## 8. Подключение настоящей отправки писем

Когда захотите, чтобы письма действительно уходили, а не печатались в
журнал.

**Сначала проверьте, что хостер не закрыл исходящий SMTP:**

```
timeout 5 bash -c '</dev/tcp/smtp.yandex.ru/587' && echo открыт || echo закрыт
```

Многие российские хостеры закрывают его по умолчанию и открывают по
заявке в поддержку.

Дальше — в `config/selectashop.toml`:

```toml
[email]
backend = "smtp"
from_address = "ваш.ящик@yandex.ru"

[email.smtp]
host = "smtp.yandex.ru"
port = 465
user = "ваш.ящик@yandex.ru"
password = "пароль-приложения"
security = "ssl"
```

**Нужен пароль приложения, а не обычный пароль от ящика.** Он создаётся в
настройках безопасности почты. Если обычный пароль вдруг сработал —
значит, у вас отключена двухфакторная защита, и это стоит исправить.

```
make config && make restart
```

Пока домена нет, письма будут уходить от вашего личного адреса. Это
годится для проверки, но не для боевой работы: лимиты жёсткие, а для
собственного адреса отправителя нужны домен и записи SPF, DKIM, DMARC.

---

## 9. Что ещё стоит сделать перед настоящим запуском

- **Купить домен** и перевести сайт на Let's Encrypt. Предупреждение
  браузера исчезнет, и можно будет включить HSTS (`[tls].hsts_seconds`).
  Сейчас HSTS выключен намеренно: с самоподписанным сертификатом он
  закрыл бы вам доступ к собственному сайту — браузер перестаёт предлагать
  кнопку «всё равно продолжить».
- **Заполнить документы** в каталоге `legal/` и показать их юристу.
- **Настроить резервное копирование** базы данных.
- **Настроить регулярный запуск** `make purge` — он удаляет просроченные
  регистрации и старые записи журнала безопасности.
