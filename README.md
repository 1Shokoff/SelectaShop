# SelectaShop

Магазин цифровых товаров. Самостоятельный хостинг на VPS в docker-контейнерах.

**Текущее состояние: этап 2** — работает регистрация с подтверждением
почты, вход, восстановление пароля и роли. Четыре контейнера: nginx,
Django, PostgreSQL и воркер рассылки.

Домен и учётная запись у почтового провайдера для проверки **не нужны**:
в режиме `console` письма печатаются в журнал воркера вместе со ссылкой
подтверждения. Пошаговый сценарий — в [docs/DEPLOY.md](docs/DEPLOY.md).

## Быстрый старт

Требования: Docker с плагином Compose, Python 3.11 или новее, `make`.

```
make init-config                       # создать config/selectashop.toml
$EDITOR config/selectashop.toml        # вписать [network].server_ip
make tls-selfsigned                    # сертификат сайта (домен не нужен)
make db-cert                           # сертификат для канала приложение <-> БД
make config                            # сгенерировать конфиги nginx и compose
make build
make up
make create-owner ARGS="--username <логин> --email <почта>"
```

Дальше откройте `https://ВАШ_IP/accounts/register/`, зарегистрируйтесь и
возьмите ссылку подтверждения из `make mail`.

Проверка: `curl -H "Host: ВАШ_IP" http://ВАШ_IP/healthz` должен вернуть `ok`.

`make init-config` сам генерирует `secret_key` и неугадываемый путь админки.
Заполнить вручную нужно только IP-адрес сервера.

## Единый файл конфигурации

Все ключевые настройки проекта собраны в одном месте:

```
config/selectashop.toml
```

Он является единственным источником правды. Из него берут параметры:

- **Django** — читает файл напрямую, смонтированный только для чтения
- **nginx** — конфиг генерируется из шаблонов в `deploy/nginx/`
- **docker compose** — переменные генерируются в `deploy/generated/.env`

После любой правки:

```
make config && make restart
```

Файл содержит секреты и намеренно внесён в `.gitignore`. В репозитории
хранится только шаблон `config/selectashop.example.toml`.

Конфигурация проверяется при генерации и отклоняется при опасных
сочетаниях параметров — например, включённая админка при выключенном TLS
не пройдёт дальше `make config`.

## Структура

```
config/
  selectashop.example.toml     шаблон, хранится в git
  selectashop.toml             рабочий файл с секретами, в git не хранится
deploy/
  nginx/                       шаблоны конфигурации nginx
  generated/                   всё сгенерированное, в git не хранится
docker/web/                    Dockerfile, entrypoint, конфиг gunicorn
scripts/                       генерация конфигов, инициализация, сертификат
src/                           приложение Django
docs/SECURITY.md               аудит безопасности
```

## Архитектура

```
           Интернет :80 / :443
                    |
            [ nginx ]              TLS, статика, rate-limit, ~9 МБ
                    |  сеть internal
            [  web  ]              gunicorn + Django, ~110 МБ
                    |  сеть data, TLS
            [   db  ]              PostgreSQL 16, ~210 МБ
                    |  сеть data
            [ worker ]             рассылка писем, ~90 МБ
                    |  сеть egress
              SMTP-релей
```

Воркер рассылки — **единственный контейнер с выходом в интернет**. Это
прямое следствие того, что очередь сообщений лежит в самой базе, а не во
внешнем брокере: приложению незачем ходить наружу.

Ни приложение, ни база не публикуют портов на хосте. Обе внутренние сети
помечены `internal: true` — они недостижимы извне и сами не могут выйти в
интернет. Единственная точка входа — порты nginx.

Сеть `data` отделена от `internal` ради одного свойства: **у nginx нет
доступа к базе данных**.

Расчёт под VPS 1 vCPU / 1 ГБ RAM: около 640 МБ суммарно, включая систему
и docker.

## Команды

```
make help              список всех команд
make config            перегенерировать конфиги из единого файла
make build             собрать образ приложения
make up / down         поднять / остановить
make restart           перезапустить оба сервиса вместе
make logs              смотреть логи
make audit             все проверки безопасности разом
make tls-selfsigned    самоподписанный сертификат сайта для работы по IP
make db-cert           сертификат для канала приложение <-> БД
make secret            напечатать новый SECRET_KEY

make create-owner   ARGS="--username ivan --email ivan@example.com"
make grant-role     ARGS="ivan admin"
make delete-account ARGS="ivan --yes"          # обезличивание
make delete-account ARGS="ivan --hard --yes"   # полное удаление
make mail              журнал воркера: тут письма в режиме console
make purge             удалить просроченные регистрации и старые события
```

Роли меняются **только командой из терминала**. Ни одна форма на сайте не
принимает поле роли — по этой же причине нет и веб-страницы «создать
первого администратора»: у такой операции не должно быть сетевой
поверхности.

`make restart` пересоздаёт оба контейнера намеренно: nginx запоминает
адрес приложения при старте, и перезапуск одного лишь `web` оставил бы
его обращаться по устаревшему адресу.

## Безопасность

Меры защиты, результаты проверок и осознанно принятые риски описаны
в [docs/SECURITY.md](docs/SECURITY.md).

Кратко, что сделано на этом этапе:

- адреса почты хранятся **только зашифрованными** (AES-256-GCM), поиск
  идёт по слепому индексу HMAC-SHA256;
- у приложения **нет прав DDL** в базе: успешная SQL-инъекция не сможет
  выполнить `DROP TABLE` или создать функцию;
- канал до базы шифруется и проверяется в режиме `verify-full`;
- база недостижима ни из интернета, ни из контейнера nginx.

TLS сайта теперь **обязателен**: `make config` откажется собрать конфиг,
если он выключен при настроенной базе данных. Раз есть база — есть формы
входа, а пароль по незашифрованному каналу недопустим.

HSTS при этом намеренно выключен. Сканеры советуют его включить, но с
самоподписанным сертификатом он **закроет вам доступ к собственному
сайту**: браузер перестаёт предлагать кнопку «всё равно продолжить».
Включать его следует после перехода на домен и Let's Encrypt.

Юридические документы в каталоге `legal/` — заготовки, их нужно заполнить
и показать юристу до запуска.

## Если сборка на сервере падает на загрузке образов

Docker Hub недоступен с российских IP-адресов. Укажите зеркало в едином
конфиге:

```toml
[project]
image_registry = "dockerhub.timeweb.cloud/"
```

затем `make config && make build`.
