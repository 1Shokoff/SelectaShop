# SelectaShop

Магазин цифровых товаров. Самостоятельный хостинг на VPS в docker-контейнерах.

**Текущее состояние: этап 0** — развёрнута инфраструктура. Работают два
контейнера: nginx и Django. Каталога, базы данных и аутентификации пока нет.

---

## Быстрый старт

Требования: Docker с плагином Compose, Python 3.11 или новее, `make`.

```
make init-config                       # создать config/selectashop.toml
$EDITOR config/selectashop.toml        # вписать [network].server_ip
make config                            # сгенерировать конфиги nginx и compose
make build
make up
```

Проверка: `curl -H "Host: ВАШ_IP" http://ВАШ_IP/healthz` должен вернуть `ok`.

`make init-config` сам генерирует `secret_key` и неугадываемый путь админки.
Заполнить вручную нужно только IP-адрес сервера.

## Единый файл конфигурации

Все ключевые настройки проекта собраны в одном месте:

```
config/selectashop.toml
```

Он является единственным источником правды. Из него берут параметры:

- **Django** — читает файл напрямую, смонтированный только для чтения
- **nginx** — конфиг генерируется из шаблонов в `deploy/nginx/`
- **docker compose** — переменные генерируются в `deploy/generated/.env`

После любой правки:

```
make config && make restart
```

Файл содержит секреты и намеренно внесён в `.gitignore`. В репозитории
хранится только шаблон `config/selectashop.example.toml`.

Конфигурация проверяется при генерации и отклоняется при опасных
сочетаниях параметров — например, включённая админка при выключенном TLS
не пройдёт дальше `make config`.

## Структура

```
config/
  selectashop.example.toml     шаблон, хранится в git
  selectashop.toml             рабочий файл с секретами, в git не хранится
deploy/
  nginx/                       шаблоны конфигурации nginx
  generated/                   всё сгенерированное, в git не хранится
docker/web/                    Dockerfile, entrypoint, конфиг gunicorn
scripts/                       генерация конфигов, инициализация, сертификат
src/                           приложение Django
docs/SECURITY.md               аудит безопасности
```

---

## Архитектура

```
              Интернет :80
                    |
            [ nginx ]              TLS, статика, rate-limit, ~9 МБ
                    |  сеть internal, наружу не выходит
            [  web  ]              gunicorn + Django, ~110 МБ
```

Приложение не публикует портов на хосте и находится в сети с
`internal: true` — оно недостижимо извне и само не может выйти в
интернет. Обе точки входа в систему — это порты nginx.

Расчёт под VPS 1 vCPU / 1 ГБ RAM: 2 воркера gunicorn по 4 потока,
лимиты контейнеров 320 МБ и 64 МБ.

## Команды

```
make help              список всех команд
make config            перегенерировать конфиги из единого файла
make build             собрать образ приложения
make up / down         поднять / остановить
make restart           перезапустить оба сервиса вместе
make logs              смотреть логи
make audit             все проверки безопасности разом
make tls-selfsigned    самоподписанный сертификат для работы по IP
make secret            напечатать новый SECRET_KEY
```

`make restart` пересоздаёт оба контейнера намеренно: nginx запоминает
адрес приложения при старте, и перезапуск одного лишь `web` оставил бы
его обращаться по устаревшему адресу.

## Безопасность

Меры защиты, результаты проверок и осознанно принятые риски описаны
в [docs/SECURITY.md](docs/SECURITY.md).

Главное, что нужно знать сейчас: **TLS выключен**, поскольку на сайте
нет ни одной формы и защищать в канале нечего. До появления регистрации
и входа его необходимо включить — `make tls-selfsigned` работает и без
домена, по IP-адресу.

## Если сборка на сервере падает на загрузке образов

Docker Hub недоступен с российских IP-адресов. Укажите зеркало в едином
конфиге:

```toml
[project]
image_registry = "dockerhub.timeweb.cloud/"
```

затем `make config && make build`.
